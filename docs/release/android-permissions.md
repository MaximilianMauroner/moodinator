# Android release permission baseline

This baseline was captured from a clean Expo Android release prebuild on
September 14, 2026. The release checker compares generated manifests against
this list so dependency changes cannot silently expand the permission surface.

## App behavior

- `INTERNET` and `ACCESS_NETWORK_STATE` are Expo/runtime defaults. Moodinator
  has no developer-operated API, analytics, advertising, or sync service;
  user-selected external links open outside the app.
- `USE_BIOMETRIC` and `USE_FINGERPRINT` support the optional local app lock.
- `VIBRATE`, `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, and `WAKE_LOCK`
  support local reminders and restoring their schedules.
- `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` is an app-scoped signature
  permission generated by AndroidX for safe dynamic receivers.

The Expo manifest merger is configured to remove legacy broad-storage,
Firebase/C2DM remote-push, Play install-referrer, and OEM launcher-badge
permissions. Moodinator uses Android's document providers for user-controlled
files, schedules notifications locally, does not read install attribution, and
explicitly disables notification badges. It also removes
`FOREGROUND_SERVICE`: AndroidX WorkManager declares the permission, but
Moodinator's Expo background backup worker uses ordinary work requests and does
not promote itself with a foreground-service API.

## Explicitly forbidden

- `android.permission.SYSTEM_ALERT_WINDOW`
- `com.google.android.gms.permission.AD_ID`

Any permission change requires a clean merged-manifest review and corresponding
Data Safety review before release.

After a clean prebuild and Gradle `:app:processReleaseMainManifest`, run
`bun run verify:android-release-manifest`. Unlike the source-only check used by
the normal fresh-checkout verification suite, this strict command fails when no
generated release manifest exists.
